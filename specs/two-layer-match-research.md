# Двухслойный match: исследование (этап 1)

Дата: 2026-11-20, сверено с main на коммите `91f239f` (комментарии в паттернах). Код не менялся. Все утверждения «работает / не работает» ниже получены прогоном на текущем `match` (около 70 проб), кроме помеченных «по коду» и «по аналогии». Пробы были разовыми скриптами и в репозиторий не вошли.

## Вывод

1. **Единая модель узла есть, и это модель, которая уже лежит в js-meta:** `{ type, ...attrs, children }`, где `children` — позиционные слоты (узел, `null` или список), а имена полей — таблица «имя → номер слота». S-выражение в ней — узел вида `List` с одним слотом-списком; головной символ — его первый элемент. Текущий `match` без единой правки матчит `(when $c $$body)`, подставляет шаблон `(if $c (do $$body))`, работает в `walk` и в смешанном дереве (JS-вызов с S-выражением в аргументе).
2. **Трудность не в модели узла, а в четырёх других местах:**
   - **Ключ диспатча не вычисляется из одного узла.** Для Lisp голова разрешается через пространство имён и область видимости. Для JS тип узла слишком груб (все макросы-вызовы попадают в `CallExpression`), нужен ключ «тип + голова», а корректная голова — это разрешённое связывание.
   - **Сравнение атомов зашито под JS.** Атрибут `value` игнорируется везде, кроме `Literal`: чужие числа `1` и `2` сейчас считаются равными.
   - **Имена типов глобальны.** Шесть из восьми проверенных типов Lua совпадают с ESTree, `define` на них падает.
   - **Где может стоять переменная, решает семейство.** Обёртки JS зашиты в `match.ts`, для TS их нет.
3. **Список паттернов из этапа 2 неполон.** По правилам пяти языков не хватает ещё четырёх примитивов: необязательный элемент, повторение группы, захват атрибута, спуск в детей до срабатывания правила (`expand`).
4. **Индекс окупается сразу.** Линейный перебор стоит около 0,23 мкс на узел за каждое правило; прототип индекса по «тип + голова» держит цену обхода постоянной при 200 правилах.

## 1. Что умеет текущий match

### Сигнатуры

```ts
match(node: Node | Node[], pattern: Node | Node[], ctx?: MatchContext): Captures | null
// Captures = Record<string, any>; MatchContext = { parent, key, index } из walk или { before: Comment[] }
rule(pattern: Node, replace: Node | null | ((m, node, ctx) => Node | null | void)): Rule
rules(...list: Rule[]): Rule            // обработчик для walk; r.once(node, ctx) — одна попытка
substitute(template, captures)          // шаблон с теми же $-переменными
```

Пара правил как они пишутся сегодня:

```js
walk(ast, rules(
  rule(js`add($a, $b)`, js`($a + $b)`),                       // шаблон
  rule(js`assert($cond)`, (m) => js`if (!${m.cond}) throw new Error(${emit(m.cond)})`),
  rule(js`log($$args)`, null),                                 // удалить
))
```

### Паттерн — это обычное дерево кода

Отдельного типа «паттерн» нет. Паттерн — `Node`, прочитанный `js`. Переменная — идентификатор с именем по регулярному выражению `^\$(\$?)([A-Za-z_][\w$]*)$`.

| Вид | Запись | Поведение |
|---|---|---|
| Литерал | любой код | тот же `type`, равные атрибуты, рекурсивно равные слоты |
| Связывание | `$a` | любой узел; повтор имени требует равного кода (сравнение тем же матчером без переменных) |
| Последовательность | `$$a` | отрезок списка, массив; несколько в одном списке, с возвратами |
| Wildcard | `$_`, `$$_` | без захвата |
| Комментарий-требование | `/* @__PURE__ */ $call` | перед узлом должен быть комментарий того же вида с тем же текстом |
| Переменная-комментарий | `/* $c */`, `/** $doc */`, `/* $$cs */` | один любой, один JSDoc, все (массив) |

Чего нет: проверки вида, альтернативы, guard внутри паттерна, необязательного элемента, частичного совпадения, захвата атрибута.

### Что зашито под JS (по коду `src/quote/match.ts`)

Это список того, что верхний слой обязан воспроизвести, чтобы тесты прошли без правок.

1. Переменная — только `Identifier` или `JSXIdentifier`.
2. Обёртки, в которых переменная означает весь элемент списка: `ExpressionStatement`, сокращённое `Property`, `PropertyDefinition` без значения, `JSXExpressionContainer`.
3. Паттерн-выражение матчит `ExpressionStatement` (проверка по регулярному выражению `/Statement$|Declaration$/` на имени типа).
4. `FunctionDeclaration` равно `FunctionExpression`, `ClassDeclaration` равно `ClassExpression`.
5. Игнорируемые атрибуты: `raw`, `shorthand`, `value`, `regex`, `bigint`, `expression`, `declare`, `comments`. Значения `undefined`, `null`, `false`, `[]` считаются отсутствием атрибута.
6. Особое сравнение для `Literal` (значение, regex, bigint), `TemplateElement` (`cooked`), `JSXText`.
7. Комментарии цели игнорируются, пока в паттерне нет своих. Комментарий паттерна ищется среди комментариев перед узлом: атрибут `comments` плюс соседи-`Comment` перед ним в списке. Отрезок `$$a` — настоящий срез списка вместе с комментариями; последний отрезок забирает и хвостовые.
8. Совпадение точное: слот `null` против узла — отказ.
9. `rule` убирает из замены комментарии, которые уже стоят перед узлом соседями, чтобы они не удвоились.

### ctx и диспатч

- `match` берёт из `ctx` одно: комментарии-соседи перед корневым узлом (`parent`, `key`, `index`). Полный `ctx` получает только функция-замена в `rule`: `parent`, `key`, `index`, `prev`, `next`, `ancestors`, `skip()`. Области видимости, позиции (expr / statement / return), хвостовой позиции, `expand` и канала вверх в нём нет. `scope(ast)` существует отдельно и считается по снимку дерева.
- Диспатча нет. `rules` на каждом узле перебирает все правила по порядку, побеждает первое сработавшее. Правило повторяется на том же узле до 100 раз. Срабатывание — на входе (внешняя форма первой), `walk` затем спускается в детей замены.
- У `walk` есть свой диспатч по типу (`{ CallExpression(node, ctx) {...} }`, группа `Function`), но `rules` им не пользуется.

### От каких структур зависит

`Node` (`type`, `children`, атрибуты как собственные свойства), глобальная таблица `SLOTS` через `slotsOf`, `attrsOf`, `make`. Позиции лежат в побочной таблице `originOf` (WeakMap) и переносятся в `walk`, а не в `match`.

## 2. Правила пяти языков

Обозначения: ✅ выражается паттерном; 🟡 выражается только функцией-заменой с ручными проверками; ❌ не выражается или даёт неверный результат.

### JS

| # | Правило | Статус | Что мешает |
|---|---|---|---|
| 1 | `assert($c)` → `if (!$c) throw …` | ✅ | |
| 2 | `{ $$before, key: $v, $$after }`, `<$T>{$$kids}</$T>`, `class $C { $$m }` | ✅ | |
| 3 | Опциональная цепочка `$a?.$b` | ❌ | `x?.y` матчится, `x?.y.z` нет: `ChainExpression` оборачивает всю цепочку, флаг `optional` сидит в глубине. Нужны спуск, свежее имя из области видимости и знание позиции (`a?.b()` сохраняет `this`) |
| 4 | `$a ?? $b` → тернарник с временной переменной | 🟡 | guard «выражение простое» и `freshName` требуют scope в ctx |
| 5 | `$a == null` и `$a === null` одним правилом | ❌ | нет альтернативы и захвата атрибута `operator` |
| 6 | Любая функция: `function $f($$p) { $$b }` | ❌ | `async` и стрелка не матчатся: атрибуты сравниваются строго |
| 7 | `const $x = $v` для `let` / `var`; несколько деклараторов `const $$d` | ❌ | атрибут `kind`; `VariableDeclarator` не обёртка |
| 8 | `if ($c) $t` с необязательным `else` | ❌ | нет необязательного слота, нужны два правила |
| 9 | `import { $$s } from 'x'`, `<$T $$attrs />` | ❌ | `ImportSpecifier` и `JSXAttribute` не обёртки |
| 10 | Свёртка `add(add(1, 2), 3)` | ❌ | результат `add(3, 3)`: правило видит нераскрытых детей и после их раскрытия не повторяется. Нужен `expand(child)` |
| 11 | Макрос, затенённый локальным именем: `function g(assert) { assert(x) }` | ❌ | раскрывается. В ctx нет scope |
| 12 | `return f(x)` как хвостовой вызов | 🟡 | позицию приходится выводить вручную из `ctx.parent` / `ctx.key` |
| 13 | `/* @__PURE__ */ $call` | ✅ | появилось в `91f239f` |
| 14 | `h($$a)` → `/* @__PURE__ */ h($$a)` | ❌ | правило матчит свой результат (есть в `specs/todo.md`). Нужно отрицание: «комментария здесь нет» |

### TS

`js` читает и синтаксис TS, так что паттерны писать можно; ограничения в матчере.

| # | Правило | Статус | Что мешает |
|---|---|---|---|
| 1 | `$x!` → `$x` | ✅ | |
| 2 | `$x as $T` → `$x` | ❌ | работает только для `foo as Bar`. `$T` читается как `TSTypeReference` с именем `$T`, поэтому `as string` и `as Bar<number>` не матчатся. То же для `satisfies`, `type $N = $T`, `f<$T>()` |
| 3 | `const $x: $T = $v` | ❌ | аннотация на переменной молча игнорируется: паттерн матчит и `const a = 1`, а `x` захватывает `a: number` целиком |
| 4 | Стирание аннотаций | ✅ без match | визитор `walk` по типу: `TSTypeAnnotation: () => null`. Нужна только «проверка вида» |
| 5 | `interface $I { $$m }`, `enum $E { $$m }` | ❌ | `TSPropertySignature` и `TSEnumMember` не обёртки; матчится только пустое тело |
| 6 | `$f($$a)` против `f<string>(1)` | ❌ | слот `typeArguments`: совпадение точное. Результат зависит от порядка «стирание, потом макросы» |
| 7 | `constructor(private $x)` → `this.x = x` | 🟡 | матчится; вставка в тело конструктора — функцией на уровне класса |
| 8 | `declare const x` отдельно от `const x` | ❌ | `declare` в списке игнорируемых (по коду) |
| 9 | Удаление `import type`, перегрузок, `abstract` | ✅ без match | по типу узла и атрибуту |

### cljs

Ридера нет, узлы и паттерны собраны руками через `define('List', ['items'])`, `Symbol` с атрибутами `ns` и `name`.

| # | Правило | Статус | Что мешает |
|---|---|---|---|
| 1 | `(when $c $$body)` → `(if $c (do $$body))` | ✅ | работает и с шаблоном, и в `walk` |
| 2 | Сравнение символов по значению | ✅ | атрибуты сравниваются по значению; два разных объекта `when` равны |

### Что из этого следует для списка паттернов

Примитивы из задания подтверждены правилами: проверка вида (TS №4, Lisp №5, Lua №3), альтернатива (JS №5, Lua №3, №6), именованные поля с частичным совпадением (JS №6, №7, cljs №8), guard с ctx (JS №4, №11).

Добавить к списку:

- **Необязательный элемент или слот** (JS №8, cljs №6, Lua №5).
- **Повторение группы** (cljs №5, Lisp №7). «Последовательность с хвостом» слабее и того, что уже есть: `$$` допускает несколько отрезков в одном списке с возвратами, и тест на это существует.
- **Захват и альтернатива атрибута** (JS №5, №6, №7).
- **Раскрытие ребёнка внутри правила** (JS №10): правило должно уметь получить уже раскрытого ребёнка.
- **Отрицание** (JS №14): «этого поля или комментария нет». В tree-sitter это `!field`.
- **Требование к комментариям перед узлом.** Уже есть в `match`, значит ядро обязано его выражать. Комментарии — не дети узла, а «то, что стоит перед ним», поэтому это отдельное поле паттерна, а не элемент списка детей.

## 3. Аналоги

| | Что это | Что взять | Что не брать |
|---|---|---|---|
| **`syntax-parse` (Racket)** | Паттерны над синтаксическими объектами: S-выражение, области видимости, позиция в исходнике, свойства | Синтаксические классы (`x:id`, `e:expr`) как именованный паттерн с guard. `~or`, `~optional`, `~seq` с многоточием — это и есть недостающие примитивы. Литералы сравниваются по связыванию, а не по имени: решает затенение. `local-expand` — наш `expand(child, ctx')`. Контексты раскрытия (expression, definition, module) — наша «позиция». Сообщение об ошибке по самому далёкому месту отказа | Наборы областей видимости на каждом узле: у нас гигиена идёт через `scope()` и `freshName` |
| **nanopass** | Язык описан грамматикой, проход — набор обработчиков по нетерминалам | Катаморфизм в паттерне (`,[e]`: «этот ребёнок уже обработан») — декларативная форма `expand`. Дополнительные аргументы обработчика — ctx вниз, дополнительные возвращаемые значения — канал вверх. Диспатч по тегу записи. Определение языка совпадает по роли с нашей таблицей слотов | Проверку выходного языка и цепочку из десятков языков |
| **Визиторы Babel** | Диспатч по типу, `path` с родителем и областью видимости, структурных паттернов нет | Слияние визиторов многих плагинов в один проход по типу — готовый образец индекса. Ленивая область видимости на `path`. Повторная постановка заменённого узла в очередь | Изменяемый `path` и ручные проверки `t.isX()`. Большая часть уже есть в `walk` |
| **Запросы tree-sitter** | S-выражения-паттерны над типизированным деревом с именованными полями: `(call_expression function: (identifier) @fn)` | Прямое доказательство, что одна запись паттерна покрывает оба семейства. Поля по имени, неупомянутые игнорируются. Квантификаторы `?`, `*`, `+`, альтернатива `[…]`, отрицание поля `!field`, wildcard `_`, супертипы, предикаты `#eq?` на стороне хоста. Все паттерны компилируются в один автомат | Нет переписывания и ctx; предикаты только постфактум |

Наблюдение по всем четырём: ни один не диспатчит по «языку». Racket диспатчит по связыванию головы, остальные по типу узла. Это совпадает с требованием задания «адаптер по типу конкретного узла».

## 4. Уточнения к этапу 2

### Модель узла

Рекомендация: ридеры всех языков выдают `Node`. Тогда `walk`, `edit`, `originOf` и структурное разделение работают без изменений, а адаптер нужен только для вещей, специфичных для семейства.

| Понятие задания | В модели |
|---|---|
| Вид | `type` с префиксом семейства: `lua/CallExpression`, `clj/list`, `clj/symbol`. ESTree остаётся без префикса |
| Ключ диспатча | пара «вид + голова». Голова: для `clj/list` — первый символ, для вызова JS — имя вызываемого, иначе пусто |
| Дети | `children`, как сейчас |
| Именованные поля | таблица слотов; у `clj/list` один слот-список |
| Значение атома | объявляется семейством: какие атрибуты значимы (`value`, или `ns` + `name`) |
| Метаданные | `originOf` и `comments` как сейчас; для cljs атрибут `meta`, в сравнении не участвует |

Адаптер семейства сводится к небольшой таблице: какие виды — комментарии (они группируются с элементом, перед которым стоят), значимые атрибуты, эквивалентные виды (декларация и выражение функции), обёртка «выражение как оператор», голова узла, позиции слотов (какой слот — оператор, какой — хвостовой). Пункты 2–7 из списка «зашито под JS» становятся адаптером ESTree, пункт 9 остаётся в `rule`.

Если формы cljs должны быть родными значениями (числа, строки, персистентные списки), то же самое выражается шестью функциями адаптера, но `walk`, `edit` и `originOf` придётся провести через него: WeakMap не принимает примитивы. Это отдельная и более дорогая работа.

### Паттерны как данные

Набросок, не окончательный:

```ts
type Pattern =
  | { p: 'lit'; value: unknown }                                  // атом по значению
  | { p: 'bind'; name: string; of?: Pattern }                     // $a, $a с условием
  | { p: 'any' }                                                  // $_
  | { p: 'node'; kind?: string | string[]; attrs?: Record<string, unknown | Pattern>;
      fields?: Record<string, Pattern>; items?: Pattern[]; exact?: boolean;
      front?: Pattern[] }                                         // комментарии перед узлом, по порядку
  | { p: 'not'; of: Pattern }                                     // отрицание
  | { p: 'rep'; of: Pattern; min: number; max: number; name?: string }   // $$a, ?, *, +, группа
  | { p: 'or'; alts: Pattern[] }
  | { p: 'guard'; of: Pattern; test: (caps, node, ctx) => boolean }
  | { p: 'expand'; of: Pattern }                                  // ребёнок раскрывается до захвата
```

Верхний слой компилирует дерево от `js` в эти данные один раз на паттерн (сейчас дерево-паттерн интерпретируется заново на каждом узле). `exact: true` и обёртки расставляет компилятор `js`, поэтому поведение сохраняется.

### Индекс и порядок

Двухуровневая таблица: вид → голова → правила, плюс правила без головы на уровне вида и правила без вида. Чтобы сохранить «побеждает первое сработавшее», у правила остаётся порядковый номер, и корзины сливаются по нему.

### Замер (базовая линия)

Семь файлов из `src/`, 15 617 узлов, ни одно правило не срабатывает, Node на этой машине, main на `91f239f`:

| Правил | Сейчас, мкс/узел | Прототип индекса, мкс/узел |
|---|---|---|
| только `walk` | 0,58 | — |
| 1 | 0,85 | 0,61 |
| 10 | 2,88 | 0,67 |
| 50 | 10,97 | 0,60 |
| 200 | 45,72 | 0,64 |

До `91f239f` линейный перебор стоил около 0,15 мкс на узел за правило, теперь около 0,23. Порог замедления решено пока не назначать (см. раздел 5); таблица остаётся как точка отсчёта.

## 5. Решения (2026-11-20)

1. **Голова правила в сахаре `js` — по имени**, как сейчас. Разрешение через связывание включается явно на нижнем уровне.
2. **Совпадение: частичное на нижнем уровне, точное в `js`.**
3. **Виды с префиксом семейства** (`lua/…`, `clj/…`), ESTree без префикса. Отдельных таблиц на семейство нет.
4. **Скорость на этом этапе не критерий.** Порог не назначается; индекс делается, потому что он входит в этап 2, а не ради цифр.
5. **Странности исправляются:**
   - аннотация на переменной (`const $x: $T = $v`) перестаёт молча игнорироваться: `$T` матчит аннотацию, а `$x` без аннотации в паттерне по-прежнему захватывает параметр целиком;
   - значение атома сравнивается у любого вида, а не только у `Literal`;
   - `declare` перестаёт игнорироваться.

   Это меняет поведение `match`, поэтому критерий «существующие тесты проходят без правок» остаётся в силе, а на каждую странность добавляется новый тест.
6. **Узлы cljs и Lisp — `Node`**, а не родные значения. Ридеры всех семейств выдают `Node`; адаптер проходит только через `match`, а `walk`, `edit` и `originOf` остаются как есть.
