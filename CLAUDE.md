# js-meta

A homoiconic runtime for JavaScript: code is data the program can read, change and print back.

**Guiding principle:** client ergonomics first. Working with code-as-data should feel like a breath of fresh air, not a chore. Clojure is the reference for homoiconicity, translated into what is canonical for JS.

## Pieces

- **read** (`src/read/`, done): `read(source, { sourceType, filename })` returns an AST.
  - The parser sits behind an adapter (`Parser`). Today it is `@typescript-eslint/typescript-estree`; it can be swapped for another JS parser.
  - The output is ESTree (JS, JSX, TS types) as plain objects with no `range`/`loc`/`parent`. Positions live in a side table: `originOf(node)`.
  - Comments are nodes (`{type:'Comment', kind, value}`) placed in the nearest list, right before their owner. There is one canonical rule and no layout flags.
  - `filename` is a module URL.
- **emit** (`src/emit/`, done): `emit(ast)` returns code in one canonical style: no semicolons (ASI-safe), no line wrapping, literals printed from `raw`. It is round-trip stable: `read(emit(ast))` deep-equals `ast`, and `emit` reaches a fixed point after one pass.
  - Printers return a Doc IR (`src/emit/doc.ts`): strings, arrays, `hardline`, `indent`, `mark(node, doc)`. It is plain data that one renderer lays out, Wadler/Prettier-style. Nothing wraps lines yet; `group`/`line` can be added later without touching printers. Decide formatting from the AST, not by inspecting printed text (`head(doc, n)` only where unavoidable).
  - `emitWithMap(ast)` returns `{ code, map }`, a Source Map v3 with `sourcesContent`. Each node start gets a segment at its origin, and Identifiers carry `names` (the source spelling, even after a rename). A node without an origin maps to its nearest ancestor that has one. `walk` gives a replacement without an origin the origin of the node it replaces, so a macro expansion maps to its call site. The loader decides how to attach the map.
  - Later: an API for printing user-defined node types (e.g. `define(type, slots, { print })`).
- **Client API with `walk`** (`src/ast/`, done; public entry `src/index.ts`): nodes, `edit`, `walk`, `b` builders, `toNode`/`toEstree`, `define(type, slots)`. The slot table lives in `src/ast/slots.ts` (seeded from visitor-keys, ours now). `read` throws on a node type or node-holding field missing from the table. A JSX `children` slot is accessed as `content`. Template literal lists (quasis/expressions) aren't interleaved, so they're the one place where slot order isn't source order.
  - Data form: an object `{ type, ...attrs, children }`, in the JS-canonical model of type + attributes + ordered children (JSX/DOM/unist). Children are positional slots: `null` for an empty slot, an array for a list of nodes (`children: [id, [a, b], body]`). Order lives in the structure, so `walk` is generic and needs no visitor-keys table.
  - Named access: one class per node type, with getters/setters mapping names to slots (`node.left` ↔ `children[0]`). `JSON.stringify` still gives the plain form. Builders (`b.binary('+', a, b)`) create class instances; `walk` also accepts bare objects, since it only needs `children`.
  - Immutable values outside, JS-style mutation inside a scoped `edit(ast, draft => { ... })` (like Clojure transients / Immer). Setters copy-on-write the node and its path to the root inside `edit`, and throw a helpful error outside it. Untouched subtrees stay `===` (structural sharing → cheap change detection and per-subtree `emit` caching). Copies inherit `originOf`. No `Object.freeze`.
  - Transform `walk` is postwalk-style: return a node to replace, `null` to remove, nothing to keep.
  - No `node.parent`: with structural sharing a node can have several parents, so context comes from the traversal. The callback gets `(node, ctx)`: `ctx.parent`, `ctx.key` (slot name), `ctx.index`, `ctx.ancestors`, `ctx.prev`/`ctx.next` (list siblings, handy for comments), `ctx.skip()`. Scope analysis is separate and lazy. A zipper (`cursor(ast)`) is possible later.
  - `scope(ast)` (`src/ast/scope.ts`): a snapshot analysis of one tree. It gives `bindingOf(id)` (Binding | null for free), `scopeOf(node)`, `root.bindings`, `free`, `names`, plus `freshName(base, names)` for hygiene. Import bindings carry `{ source, name }`. TS type positions are skipped (not values). JSX components (`<Foo />`) are references. The loader uses it to rewrite imported names into live namespace reads.
  - Visitor: `walk(ast, fn | visitor)`. A function is enter-for-all. An object has keys by type, group aliases (`Function` first, defined in the slot table), `{ enter, leave }` per key, and generic `enter`/`leave`. `walk` returns the new root (`===` if unchanged). A replacement from `leave` is postwalk; one from `enter` is prewalk (descend into the replacement's children without re-entering it, so nested macros expand with no loops). Selectors and visitor merging come later.
  - ESTree objects stay as the boundary with the outside world: the parser produces them and `emit` consumes them. The ESTree ↔ children conversion holds the only per-type slot table.
  - `walk` visits comments too.
  - Later: an optional JSX API layer for building nodes.
- **Quasiquote and `match`** (`src/quote/`, done): rewrite rules read as code: `const m = match(node, js\`$a + $b\`); if (m) return js\`add(${m.a}, ${m.b})\``.
  - `` js`...` `` reads a template once per call site (cached by `strings`), with placeholder identifiers in the holes, and returns nodes without origins (they inherit the call site's in `walk`). Grammar: expression first (`{ a }` is an object, `function f() {}` an expression), else one statement; `js.stmt` (strict, `{}` is a block), `js.stmts` (array). Raw template text is the source, so `'\n'` stays an escape.
  - `${value}` is always a value from JS, put in by position: a node as is, adapted (an expression becomes a statement where one goes, a named function/class expression becomes a declaration and back); an array splices into a list (args, params, body, properties, class members, JSX children `{${kids}}`); a string is an identifier only where only a name goes (binding, key, `a.${name}`, invalid names become `'my-key'` / `a['my-key']`), elsewhere a string literal; `js.id(name)` for an identifier expression. number/boolean/null/bigint/RegExp are literals; `undefined`, functions and plain objects are errors naming the hole.
  - `match(node, pattern)` returns captures or null. In patterns `$a` captures any node, `$$a` a run of list elements (array, backtracking), `$_`/`$$_` don't capture; a repeated variable must match equal code. Variables also stand for a whole list element: statement, shorthand property, class member, JSX child. Ignored: comments, layout, literal spelling, `shorthand`, default-valued attrs. An expression pattern matches an expression statement; function/class declarations and expressions match each other.
  - Later: rule sugar for `walk` (`pattern → template`), predicates in patterns, hygiene for names a template introduces (via `freshName`).
- **Module system** (planned): a module cache that starts out loaded from ESM, then mirrors the loaded modules live at runtime.
- **Loader** (`src/loader/`, MVP done): rewrites the imports in each `.js` file to point at our module system.
  - `Runtime` (`runtime.ts`): `records` (url → record with kind, status, namespace, dependencies, importers, source, ast, code, map) is the live module map. `import()` runs two phases: `loadGraph` fetches, reads and lowers the static graph in parallel, with a visited set so cycles don't wait on themselves; `evaluate` then runs it depth-first, where back edges of a cycle get the namespace as it is. Code is run by indirect eval with `sourceURL=<url>#js-meta` and an inline source map. `bootstrap(entry)` and `runtime()` share one runtime per page. `src/app.ts` boots `src/demo/main.js`.
  - Live redefinition, Clojure-var style (done): top-level bindings are cells in the record's `env` (`env.count`, `env.inc = function inc() {...}`, hoisted). `runtime.redefine(url, source | ast)` compares top-level forms by canonical `emit` text and runs only new or changed forms (`lower(ast, { include })`) into the same env. Unchanged state stays, callers reach new definitions through the cells, and importers read namespace getters, so nothing else re-runs. A changed initializer re-runs (like `def`). Removed bindings and exports are deleted, new imports are loaded and join the graph. Known gap: no TDZ for top-level `let`/`const`.
  - Next: `import.meta.hot.dispose` for side effects, JSX/TS lowering passes, import attributes, a REPL-like `runtime.eval(url, code)`.
  - Deferred: a file-change trigger. A full page reload on save is fine for now. ts-code's livereload client always reloads (no extension point), and ts-code will be redesigned for modularity, so revisit then. js-meta's side would be a transport-free `runtime.update(urls)`: redefine our records, fall back to a reload for anything else.
  - Chosen: our own module format plus a small runtime (like Vite SSR / SystemJS), not native ESM via blob URLs and not a service worker. Modules are records in a registry and exports are getters, so a module can be redefined live (like a Clojure var) and the import graph is live too. The page starts with `bootstrap(entry)`. Every import goes through the runtime's `import()`. Our modules are rewritten; modules we don't parse (esm.sh, bare specifiers, `.ts` for now) are native `import()` wrapped as records.
  - The per-module object is `import.meta`, the host object ESM already gives each module. Precedent: the standard `import.meta.resolve()`, Vite's `import.meta.hot`, Node's `import.meta.dirname`. Lowering for execution turns static and dynamic imports into `import.meta.import(spec)` and exports into `import.meta.export({ name: () => binding })` at the top of the body (getters: live bindings, ESM-like TDZ, hoisted functions). Then, since `import.meta` is a syntax error outside a native module, `import.meta` becomes the wrapper parameter: `(async function (meta) { ... })`, renamed hygienically (`meta_1`, ...) on a clash. No globals. Runtime extensions also live on `import.meta.*`. The global runtime API (bootstrap, registry, live graph) is exported from the package, not injected.
  - `lower(ast)` (`src/loader/lower.ts`, done) returns `{ ast, imports, exports, exportsAll }`. Imported names become namespace reads via `scope()`: `a` → `b.a`, `a()` → `(0, b.a)()`, `{ a }` → `{ a: b.a }`, `<A />` → `<b.A />`. The body gets `'use strict'`. Runtime contract: `meta.import(spec)` resolves to a namespace, `meta.export(getters)`, `meta.exportAll(ns)`, `meta.url`. Plain JS only for now: JSX and TS need their own lowering passes before eval.
  - Users and macros work on canonical ESM (`import`/`export` as written). The lowering is a compile step before execution, visible only in generated code, and source maps hide it.

## Constraints

- Everything runs on the page, in the browser, in one thread, so the AST always matches the live code. The same code also runs in Node for tests.
- The dev server is `ts-code` (`pnpm dev`, port 3000). It transpiles TS→JS in a service worker and does livereload. Don't touch its runtime.
- Packages listed under `dependencies` are mapped to esm.sh by ts-code. Build options go in `package.json` → `"ts-code"."esm.sh"`. TypeScript is shared with the parser through `external=typescript`.
- The project targets JS. TS is supported only as far as ESTree carries it. A separate project may handle TS later.

## Dev

- Install: `pnpm i`. npm is blocked by `devEngines`.
- Tests: `pnpm test` (`node --test`; Node runs `.ts` directly). Imports use explicit `.ts` extensions. Don't add vitest.
- Type-check: `pnpm exec tsc` (`noEmit`, `erasableSyntaxOnly`).
- Discuss design with the user before coding new pieces.
